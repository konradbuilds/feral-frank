    Storage & history

    Details

    Choose how much chat history Frank keeps. This controls Frank’s saved text, not browser RAM, AI intelligence or the amount sent to a model.

    Saved text and message count are useful checks. Where available, JavaScript heap is an approximate diagnostic, not total tab RAM. It excludes artwork, browser overhead and some other memory. Frank cannot enforce a RAM cap. Updates pause when this tab is hidden.

    Low: 256 KiB / 40 messages. Medium (default): 2 MiB / 200. High: 3 MiB / 500. Extra high: 4 MiB / 1,000. These are ceilings; Frank does not allocate that much just because you select it. More messages can make loading slower.

    The cap includes Frank’s chat, facts, notes and preferences. Size is estimated from stored UTF-16 text; your browser may impose a smaller quota. Offline artwork/cache and private provider keys are separate. Other websites’ data is untouched.

    Oldest chat messages roll off first. Saved personal facts and scratch notes are protected; if those cannot fit, new saves stop and a warning appears. Lowering a profile shows exactly how many current messages would be removed before you apply it. Deleting chat does not erase facts already kept in memory.

    How Frank works

    Add an AI API key in AI connection. Frank checks your key and model before enabling chat.

    Your model receives Frank’s character brief, recent chat and relevant saved memories. Review or delete memories here at any time. Notes stay on this device unless you bring them into chat.

    Public previews are scripted and clearly labelled. Live chat requires your own installation and AI connection. Frank’s moods are fictional; stored memories are editable data, not model training.

    Entertainment, with fictional needs and moods. No analytics. Browser storage holds your chat and memory; clearing browser data removes them. With AI enabled, your message, recent chat and selected memories go to the configured backend.
